    Asymmetrische Verschlüsselung mittels RSA

    Einführung

    Während bei der symmetrischen Verschlüsselung beide Kommunikationspartner denselben geheimen Schlüssel verwenden, arbeitet die asymmetrische Kryptographie mit einem Schlüsselpaar:

    • einem öffentlichen Schlüssel (Public Key)
    • einem privaten Schlüssel (Private Key)

    Der öffentliche Schlüssel darf frei verteilt werden. Der private Schlüssel bleibt geheim.

    RSA ist eines der bekanntesten Public-Key-Verfahren. Es wird verwendet für:

    • Verschlüsselung
    • Digitale Signaturen
    • Zertifikate
    • Authentifizierung
    • Schlüsselaustausch in hybriden Kryptosystemen

    Die Sicherheit von RSA beruht auf einer mathematischen Einwegfunktion: Das Multiplizieren großer Primzahlen ist einfach, die Faktorisierung ihres Produkts hingegen äußerst aufwendig.

    In dieser Übung lernst du die mathematischen Grundlagen von RSA kennen, erzeugst eigene Schlüsselpaare, verschlüsselst und signierst Nachrichten und untersuchst, wie RSA heute in realen Sicherheitssystemen eingesetzt wird.

    Ziele

    • symmetrische und asymmetrische Kryptographie unterscheiden
    • den Aufbau eines RSA-Schlüsselpaares erklären
    • die Bedeutung von Primzahlen und Modulo-Arithmetik erläutern
    • die Euler'sche φ-Funktion anwenden
    • RSA-Schlüssel erzeugen
    • Nachrichten verschlüsseln und entschlüsseln
    • digitale Signaturen erstellen und verifizieren
    • die Grenzen von RSA beurteilen
    • erklären, warum RSA heute meist in hybriden Kryptosystemen eingesetzt wird
    • die Rolle von RSA-Zertifikaten in HTTPS beschreiben

    Kompetenzzuordnung

    Grundlagen der IT Sicherheit

    • die grundlegenden Begriffe der Kryptographie erklären;
    • die Funktionsweise kryptographischer Verfahren erklären und anforderungsgerechte Verfahren auswählen

    Methoden und Verfahren der IT-Sicherheit

    • Werkzeuge zur Verschlüsselung konfigurieren und einsetzen

    Voraussetzungen

    • Python Runtime installiert: Welcome to Python.org (kann auch direkt mittels Microsoft Store installiert werden)
    • CrypTool2 installiert: CT2 Downloads – CrypTool
    • GnuPG installiert: The GNU Privacy Guard bzw. Gpg4win - Sichere E-Mail- und Datei-Verschlüsselung mit GnuPG für Windows
    • Chat Client vorbereitet: siehe angehängte .7z Datei (Passwort: lfb)

    Aufgabe Grundkompetenz:

    Teil 1 – Multiplizieren vs. Faktorisieren

    Auch in der Mathematik gibt es Operationen, die einfach und schnell auszuführen sind. Die Umkehrung jedoch ist selbst für einen Computer aufwändig und kann Jahre dauern.

    Ein Beispiel dafür ist das Multiplizieren zweier (Prim-)Zahlen. Jeder Computer kann pro Sekunde mehrere Milliarden Multiplikationen ausführen. Ein Produkt zweier Primzahlen in die beiden Faktoren zu zerlegen, ist jedoch ungleich aufwändiger – insbesondere wenn die Zahlen mehrere hundert Stellen lang sind.

    Die Sicherheit von RSA basiert auf einem einfachen Prinzip:

    Multiplikation = einfach
Faktorisierung = schwierig

    Multiplikation

    Berechne:

    41 · 83

    mittels schriftlicher Multiplikation.

    Beschreibe deinen Lösungsweg.

    Faktorisierung

    Gegeben:

    3397

    Bestimme die beiden Primfaktoren.

    Beschreibe:

    • Wie bist du vorgegangen?
    • Welche Zahlen hast du getestet?

    Recherchiere folgende Faktorisierungsverfahren:

    • Probedivision
    • Fermat-Faktorisierung
    • Pollard-Rho
    • Quadratic Sieve
    • General Number Field Sieve

    Beschreibe jeweils kurz:

    • Grundidee
    • Einsatzgebiet

    Reflexion

    Begründe:

    • Warum ist Faktorisieren deutlich schwieriger als Multiplizieren?
    • Weshalb ist dies für RSA wichtig?

    Teil 4 – Blocklänge

    RSA verarbeitet Zahlen.

    Texte müssen daher zuerst in Zahlenblöcke umgewandelt werden.

    Jetzt verschlüsseln wir einen String.

    Bei RSA ist die Blocklänge ein wichtiger Aspekt, weil sie direkt beeinflusst, wie die Daten vor der Verschlüsselung segmentiert werden.

    Führ die Umwandlung eines Strings in eine natürliche Zahl durch:

    1. Verkürze deinen Nachnamen auf 7 Zeichen.
    2. Wandle den Namen in eine Bytefolge um.

    Aus einer Liste aus Bytes (dargestellt als Zahlen aus dem Bereich 0..255) kann man jetzt die Zahlen erzeugen, die letztlich vom RSA-Verfahren verarbeitet werden. Hierbei muss allerdings beachtet werden, dass die zu verarbeitenden Zahlen kleiner als die Zahl n eines Schlüsselpaares (e, n) oder (d, n) sind.

    1. Stelle die Bytefolge im 256er-System dar.

    Damit die so erzeugte Zahl z die Bedingung z < n erfüllt, muss die Anzahl der Bytezahlen, die zur Erzeugung von z benutzt werden, eingeschränkt werden. Für die Anzahl b der Bytezahlen muss die Bedingung 256b-1 < n gelten. Wenn z.B. n = 3001122295343 vorgegeben ist, so erhält man b = 5 als maximale Byteanzahl. Die Zahl b legt demnach die Byte-Blocklänge fest.

    Ein RSA-System verwendet:

    2048 Bit

    Bestimme:

    1. Maximale theoretische Blockgröße (in Bytes) ohne Padding.
    2. Nutzbare Blockgröße mit PKCS#1 v1.5 Padding (Padding benötigt mindestens 11 Bytes).

    Beantworte:

    • Kann dein Nachname in einem Block verschlüsselt werden?
    • Warum eignet sich RSA nicht zur Verschlüsselung großer Dateien? Wie kann dieses Problem gelöst werden?

    Teil 10 – RSA und digitale Zertifikate

    Eine der wichtigsten Anwendungen von RSA ist heute die Verwendung in digitalen Zertifikaten.

    Ein digitales Zertifikat dient dazu, die Identität eines Kommunikationspartners nachzuweisen. Es enthält unter anderem:

    • den Namen des Inhabers,
    • den öffentlichen Schlüssel des Inhabers,
    • Angaben zur Gültigkeit,
    • eine digitale Signatur einer Zertifizierungsstelle (Certificate Authority, CA).

    Dadurch kann überprüft werden, ob ein öffentlicher Schlüssel tatsächlich zu einer bestimmten Person, Organisation oder Webseite gehört.

    RSA wird dabei häufig verwendet, um Zertifikate zu signieren oder die darin enthaltenen öffentlichen Schlüssel bereitzustellen.

    Zertifikate verstehen

    Recherchiere:

    1. Was ist ein digitales Zertifikat?
    2. Welche Informationen enthält ein X.509-Zertifikat?
    3. Was ist eine Certificate Authority (CA)?
    4. Welche Aufgabe hat eine CA?
    5. Warum genügt es nicht, einen öffentlichen Schlüssel einfach per E-Mail zu verschicken?

    Erstelle zusätzlich eine Skizze, die folgende Situation zeigt:

    Alice → erstellt Schlüsselpaar → Certificate Authority → signiertes Zertifikat → Bob prüft Zertifikat

    Beschreibe die Aufgaben aller Beteiligten.

    Zertifikate überprüfen

    Angenommen Bob erhält folgendes:

    Nachricht + Öffentlichen Schlüssel von Alice

    Woher weiß Bob, dass der öffentliche Schlüssel wirklich Alice gehört?

    Beschreibe, wie ein Zertifikat dieses Problem löst.

    Gehe dabei auf folgende Begriffe ein:

    • Vertrauen
    • Digitale Signatur
    • Fingerprint
    • Certificate Authority
    • Öffentlicher Schlüssel der CA

    Beantworte:

    • Warum sind Zertifikate für asymmetrische Kryptographie so wichtig?
    • Welches Problem würden Zertifikate lösen, das in den bisherigen RSA-Aufgaben noch nicht betrachtet wurde?
    • Warum ist die Authentizität eines öffentlichen Schlüssels oft wichtiger als dessen Verteilung?
    • Welche Folgen hätte ein gefälschtes Zertifikat?
